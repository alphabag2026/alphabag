# AlphaBag A포인트·B포인트 운영 정책

**상태:** 구현 기준 정책 · 실자금 출금 전 운영·법률 검토 필요

> A포인트와 B포인트의 `1점 = 1 USDT`는 플랫폼 내부 산정 기준이다. B포인트 USDT 출금은 자동 보장이 아니라 실제 확인된 준비금, KYC 승인, 관리자 심사 및 온체인 송금 완료를 전제로 한다.

## 1. 포인트 정의

| 구분 | A포인트 | B포인트 |
|---|---|---|
| 내부 기준가 | 1 A = 1 USDT | 1 B = 1 USDT |
| 지급 목적 | 프로젝트 실패 회원 유입, 레그 이동, 관리자 승인 보상 | 승인된 A→B 전환으로만 생성 |
| 회원 간 전송 | 가능 | 불가 |
| 투자 결제 | 가능, 투자금의 5~30% | 불가 |
| USDT 출금 | 불가 | 준비금 범위에서 신청 가능 |
| 현금성 위험 | 비출금성·투자 사용성 | USDT 청구 가능성이 있어 준비금·KYC·승인 필요 |

## 2. A포인트 지급

A포인트는 다른 프로젝트가 실패한 뒤 사용자가 AlphaBag 회원으로 가입한 경우, 기존 조직에서 AlphaBag 조직으로 레그 이동이 승인된 경우, 또는 예외적인 관리자 조정 사유가 있는 경우에 지급한다. 모든 지급은 신청·증빙·관리자 승인·원장 기록의 네 단계로 처리하며 승인 전 잔액에는 반영하지 않는다.

## 3. A포인트 전송

활성 계정의 사용자는 보유 가능한 A포인트 범위에서 다른 AlphaBag 회원에게 A포인트를 전송할 수 있다. 전송은 보내는 사람 차감과 받는 사람 적립을 하나의 데이터베이스 트랜잭션으로 처리하며, 전송 후 취소는 일반 기능으로 제공하지 않는다. 동결 계정, 자기 자신, 존재하지 않는 회원 및 잔액 부족 전송은 거부한다.

## 4. 투자 복합 결제

투자금은 USDT 70~95%와 A포인트 5~30%로 구성하며 합계는 100%여야 한다. 1,000 USDT 투자에서 70/30 정책은 700 USDT와 300 A, 95/5 정책은 950 USDT와 50 A를 사용한다. 신청 시 A포인트를 예약하고, 관리자가 실제 USDT 결제 네트워크와 TxHash를 확인해야 `confirmed` 상태가 된다. 확인되지 않은 투자 결제 의도는 완료하거나 B포인트로 전환할 수 없다.

## 5. A→B 전환

전환율은 1 A = 1 B다. 투자 완료 전환은 관리자가 해당 투자 사용 건의 완료를 승인할 때, 그 투자에 사용된 A포인트 수량을 B포인트로 전환한다. 100% USDT 매출 전환은 연결 가능한 프로젝트가 없는 상태에서 100% USDT 매출이 증빙된 경우에만 신청할 수 있으며, 매출액의 5~30%에 해당하는 A포인트를 차감하고 같은 수량의 B포인트를 지급한다.

전환은 A 차감과 B 적립을 하나의 데이터베이스 트랜잭션으로 처리한다. 동일 투자·매출 증빙의 중복 승인을 막기 위해 요청 ID와 원장 멱등 키를 보존한다.

## 6. B포인트 USDT 출금

1 B는 1 USDT 출금 신청액으로 산정한다. 신청 시 사용자의 B포인트를 예약 잔액으로 이동시키며, 활성 준비금 계정의 가용 준비금이 부족하면 승인할 수 없다. 관리자가 승인하면 준비금을 커밋하고, 온체인 USDT 송금 후 TxHash를 입력해야 `paid` 상태로 완료된다. 거절·실패 시 예약 B포인트와 준비금 커밋을 원복한다.

## 7. 회계·감사 원칙

잔액 테이블은 현재 상태를 빠르게 조회하기 위한 스냅샷이며, 거래 원장이 감사의 기준이다. 지급, 전송, 투자 사용, 전환, 출금 예약·원복·완료는 각각 독립된 멱등 원장 행으로 기록한다. B포인트 총부채는 준비금과 매일 대조하고, 준비금 부족 시 신규 B 전환과 출금 승인을 일시 중지한다.
